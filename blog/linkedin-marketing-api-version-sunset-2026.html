LinkedIn Marketing API 202510 and 202511 Sunset in 2026: What Breaks and How to Check

LinkedIn retires a Marketing API version every month, and two of them go this quarter. Most teams affected will never see the API. They will see an empty report. Here is how to find out first.

Distk Editorial Oct 2026 10 min read

LinkedIn's changelog lists two Marketing API sunsets this quarter: "202510 - Oct 15, 2026" and "202511 - Nov 16, 2026". Versions are selected with the Linkedin-Version request header in YYYYMM format and are supported for a minimum of one year, and LinkedIn returns an error rather than falling back when a request uses a deprecated or missing version. That means any reporting script, CRM connector, audience sync or automation tool still sending either version stops working on those dates. To check, search owned code and configuration for Linkedin-Version and get each vendor's version in writing. Migrating means changing the header and testing what changed between versions, ideally to 202609, which LinkedIn supports until 15 September 2027. Moving to 202608 or later also unlocks the new MQL and SQL conversion types.

What Is Changing in the LinkedIn Marketing API in October and November 2026?

Two LinkedIn Marketing API versions are being switched off. LinkedIn's changelog lists "202510 - Oct 15, 2026" and "202511 - Nov 16, 2026" under Version Sunset, and its developer pages carry a standing banner: "The Marketing Version 202510 (Marketing October 2025) will be sunset on October 15, 2026." Any tool still sending either version after those dates stops getting normal responses.

This is routine for LinkedIn, which releases a new API version every month, but it lands hard on agencies and B2B teams because almost nobody using LinkedIn ads through software knows which version their tools call. Reporting dashboards, CRM connectors, audience sync tools and in-house scripts all send a version, and the oldest ones in production are usually the ones nobody has touched in a year.

Explain It Like I Am Five

The simple version

Every time your software talks to LinkedIn, it says which edition of the rulebook it is reading from, like quoting the year on a phone directory. LinkedIn prints a new directory every month and promises to keep each one working for at least a year. After that, it throws the old directory away. If your tool keeps quoting last year's edition, LinkedIn stops answering it. Nothing about your ads changes. The tool that reads or manages them just goes quiet, and often nobody notices until a report comes back empty.

How Does LinkedIn Marketing API Versioning Work in 2026?

LinkedIn versions its Marketing API by month and identifies each version with a request header. Its versioning page says: "Include a request header with the key 'Linkedin-Version' and set the value to the version (format: YYYYMM)." It adds that "These API versions are supported and stable for a minimum of one year before sunset." Each version is therefore a dated contract with roughly a twelve month life.

The header in LinkedIn's own example looks like this:

-H 'Linkedin-Version: 202601' \

Two behaviours matter for anyone running production tooling in 2026. LinkedIn states that "An error response is returned when the version header is missing in the request", and that "An error response is returned when the version header is deprecated (e.g., 202401)." There is no silent fallback to a newer version. A tool sending a sunset version gets an error, not slightly different data.

Who Is Affected by the 202510 and 202511 Sunsets?

Anyone whose software calls the LinkedIn Marketing API with either version header, which is a wider group than developers. Agencies and in-house teams are affected even if they never write code, because the tools they rely on make the calls on their behalf. The risk sits with whoever built or maintains the integration, but the consequence shows up in the marketing team's reports and campaigns.

  • Agencies with custom reporting: scripts or BI connectors pulling ad analytics into dashboards for clients.
  • B2B teams with CRM sync: integrations sending lead or conversion data between LinkedIn and a CRM.
  • Audience and ABM tooling: anything creating or updating matched audiences or company lists.
  • Campaign automation: bulk campaign creation, budget pacing or bid tools that manage campaigns through the API.
  • Third-party martech platforms: usually maintained by the vendor, but worth confirming in writing rather than assuming.

How Do You Check Which Version Your Tools Use in 2026?

Look for the header value. For code you own, search the codebase and any configuration for the string Linkedin-Version and read the value next to it. For tools you do not own, ask the vendor which Marketing API version they currently send and when they plan to move. The answer you want is a version from 2026, not 202510 or 202511.

  1. Inventory every LinkedIn integration touching your ad accounts: reporting, CRM, audiences, automation, and any freelancer-built scripts.
  2. Search owned code and config for Linkedin-Version, including environment variables and scheduled jobs.
  3. Email each vendor and ask for the version in use and their migration date, in writing.
  4. Check error logs for version errors after any earlier sunset, such as 202509 on 15 September 2026. An integration that broke then and was patched quietly may be close to the line again.
  5. Note which tools depend on newer features, because some 2026 capabilities only exist on recent versions.

What Should You Do Before 15 October 2026?

Move every integration to a current version, ideally the latest. LinkedIn's migration guidance is that "To migrate your app from an older version to a later version, simply update the older version's YYYYMM formatted value in the header to the newer version's value." Changing the header is trivial. Testing what changed between versions is the real work, and that is why it should start now rather than on 14 October.

Why Is Upgrading Worth More Than Avoiding an Outage in 2026?

Because several of LinkedIn's most useful 2026 changes only exist on recent versions. Staying on an old header does not just risk a shutdown. It also leaves capabilities unused that matter for B2B performance, particularly around lead quality and measurement.

  • Marketing and sales qualified lead conversion types: LinkedIn states MARKETING_QUALIFIED_LEAD and SALES_QUALIFIED_LEAD "are available starting with the 202608 version onwards." Our Conversions API qualified leads guide explains why they matter.
  • Hashed name matching: the hashedFirstName and hashedLastName fields arrive "Starting with the 202609 version."
  • Account-level dynamic UTMs: setting tracking parameters for a whole ad account starts "with the 202608 version."
  • Company Intelligence filters and a 365-day lookback: the 365-day window starts with 202606, and LinkedIn notes "Versions 202605 and earlier continue to cap the window at 180 days."

What Are the Common Mistakes in 2026?

  • Assuming a tool you pay for is already upgraded. Ask for the version in writing.
  • Searching for 202610 or 202611. Those are mislabels from automated summaries. The sunsetting versions are 202510 and 202511.
  • Changing the header without testing. The header is one line; behaviour differences are not.
  • Upgrading only to the next version. Jumping to 202511 buys about a month. Move to a 2026 version.
  • Forgetting freelancer-built scripts. They are the integrations most likely to be on an old version and least likely to be monitored.
  • Treating it as a developer problem. The first symptom is usually an empty or incomplete client report.

Key Questions

LinkedIn API Version Sunsets in 2026: FAQs

When do LinkedIn Marketing API versions 202510 and 202511 sunset?

LinkedIn lists "202510 - Oct 15, 2026" and "202511 - Nov 16, 2026" in its September 2026 changelog. Its developer pages also state the October 2025 version will be sunset on October 15, 2026.

What happens if my tool keeps calling a sunset version?

LinkedIn states that an error response is returned when the version header is deprecated. There is no automatic fallback to a newer version, so the integration stops returning normal results.

How do I find out which LinkedIn API version my tools use?

Search code and configuration you own for the Linkedin-Version header and read its value. For third-party tools, ask the vendor which Marketing API version they send and when they will migrate, and get the answer in writing.

Are the sunsetting versions 202610 and 202611?

No. That is a mislabel that appears in some automated summaries. LinkedIn's own sunset lists name 202510 and 202511, the October and November 2025 releases.

Which version should we migrate to?

Normally the latest, 202609, which LinkedIn's migration table shows as supported until September 15, 2027. Moving to just the next version only buys weeks.

Does upgrading unlock anything besides avoiding an outage?

Yes. MARKETING_QUALIFIED_LEAD and SALES_QUALIFIED_LEAD conversion types require 202608 or later, hashed first and last name matching requires 202609, and account-level dynamic UTMs require 202608.
